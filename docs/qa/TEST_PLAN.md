# 협동 게임 테스트 계획

1~8 은 **협동·플랫폼 공통 항목**, 9 는 정해진 게임 **B. 등불 원정대**(`docs/design/CONCEPTS.md`) 전용 항목이다.
기획서가 자세해지면(수치, 직업, 층 구성) 9 를 늘린다.

- **자동**: `tests/` 테스트 씬으로 CI 에서 돈다 (`TESTING.md` 규칙).
- **자동(예정)**: 자동으로 만들 수 있지만 개발팀 기능(아래 "개발팀에 필요한 것")이 먼저 있어야 한다.
- **수동**: 사람이 직접 확인한다. 릴리스 후보마다 체크리스트를 복사해 결과를 `docs/qa/runs/<날짜>.md` 에 남긴다.

ID 는 버그 이슈와 PR 에서 참조한다 (예: `NET-03`).

| LAG-04 | 실제 스팀 릴레이로 먼 거리(다른 지역) 친구와 30분 플레이 | 수동 |

### 헤드리스로 흉내 내는 방법

1. **리눅스 `tc netem` (CI 에서 가능, 추천)**: GitHub Actions 우분투 러너는 `sudo` 가 되므로 루프백에 지연·손실을 건다.
   한 프로세스 안에서 여러 피어를 돌리는 테스트에도, 여러 프로세스 테스트에도 그대로 적용된다.
   ```bash
   sudo tc qdisc add dev lo root netem delay 100ms 20ms loss 1%   # LAG-01
   sudo tc qdisc change dev lo root netem delay 250ms 50ms loss 5% # LAG-02
   sudo tc qdisc change dev lo root netem loss 100%; sleep 3; sudo tc qdisc change dev lo root netem loss 0%  # LAG-03
   sudo tc qdisc del dev lo root
   ```
   루프백 전체에 걸리므로 이 테스트들은 따로 CI 작업으로 분리한다 (다른 테스트를 느리게 만들지 않게).
2. **게임 안 디버그 지연 장치 (개발팀 요청)**: 네트워크 계층에 송수신 지연·버리기 비율을 넣는 디버그 옵션.
   `tc` 가 안 되는 곳(윈도우, 클라우드 세션 컨테이너)에서도 돌 수 있다.
3. Steam 릴레이 구간은 흉내 낼 수 없으므로 LAG-04 는 수동.

## 9. 등불 원정대 전용 (LANT)

호스트 권한이 기본: 던전 시드·기름·괴물 AI·쓰러짐 판정은 호스트가 정하고 클라이언트는 받는다.

### 던전 생성 (시드)

| ID | 확인할 것 | 방식 |
|---|---|---|
| LANT-01 | 같은 시드로 두 번 생성 → 방·통로·문·함정·유물·기름통 배치가 완전히 같음 (생성 결과 요약 해시 비교) | 자동(예정) |
| LANT-02 | 여러 시드(예: 100개)로 생성 → 모두 입구에서 엘리베이터·다음 층 계단까지 길이 이어짐, 막힌 방 없음 | 자동(예정) |
| LANT-03 | 호스트가 정한 시드가 2~4인 모든 클라이언트에 전달되고, 각 클라이언트에서 만든 던전 해시가 호스트와 같음 | 자동(예정) |
| LANT-04 | 생성 결과가 실행 환경(Windows / Linux / Steam Deck)과 무관하게 같음 — 생성에 전역 `randi()`·딕셔너리 순서·물리 결과를 쓰지 않음 | 자동(예정): CI 리눅스 해시를 기준값으로 저장 + 수동(Windows 에서 같은 해시) |
| LANT-05 | 층 이동 시 새 시드(또는 시드+층 번호)로 모든 피어가 같은 다음 층을 만듦 | 자동(예정) |

| ID | 확인할 것 | 방식 |

## 개발팀에 필요한 것 (자동(예정) 항목을 위해)

이슈로 요청할 것. 기반 코드(`dev/foundation`)가 올라오면 맞춰서 구체화한다.

1. 네트워크 계층을 Steam 없이 ENet 만으로 쓸 수 있는 방법 (테스트에서 직접 호스트·접속 호출).
2. 명령줄 인수로 헤드리스 호스트/접속 시작: 예 `-- --host --port 7777`, `-- --join 127.0.0.1:7777` (여러 프로세스 테스트용).
3. 끊김 판정 시간을 설정으로 바꿀 수 있게 (테스트가 오래 기다리지 않게).
4. 네트워크 디버그 지연·손실 옵션 (LAG 항목, 위 "흉내 내는 방법" 2번).
5. 게임 상태를 비교할 수 있는 요약 함수 (예: 모든 피어에서 같은 값이 나와야 하는 상태 해시).
6. 던전 생성기를 시드만 받아 화면 없이 돌릴 수 있게, 결과 요약(해시)을 돌려주는 함수 (LANT-01~05). 생성 안에서는 시드로 만든 `RandomNumberGenerator` 만 쓰기.
7. 기름·쓰러짐·괴물 상태를 테스트에서 읽을 수 있는 방법 (호스트·클라이언트 각각).
