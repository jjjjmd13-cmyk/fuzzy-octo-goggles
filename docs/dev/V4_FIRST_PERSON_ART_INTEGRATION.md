# V4 1인칭 도구·장갑 연결 검수 — 2026-10-30

PR #71의 원본 GLB/Blender 미리보기/생성 소스를 그대로 재사용했다. 최신 main의 V4 수치표(#70)도 보존한다. 메뉴의 **V4 시제품 (1인칭)** 또는 `scenes/v4/fp_shop.tscn`에서 확인한다.

## 자산 검토와 연결

| 자산 | 검토 | V4 사용 |
|---|---|---|
| shower.glb | 2,108삼각형, 3 surface, 쥐는 곳 원점 | 선반/오른손, 실제 분사구에서 물줄기 |
| shampoo.glb | 1,392삼각형, 3 surface, 병 중앙 원점 | 민트 병, 발바닥 라벨을 사용자 쪽으로, 손목을 기울여 사용 |

| dryer.glb | 1,224삼각형, 4 surface | 원본/임포트/미리보기 보존, 현재 선택 목록에는 없음 |

모두 미터/Y-up/-Z 전방, 외부 텍스처 및 애니메이션/스킨 없음. GLB JSON의 실제 인덱스·재질·bounds와 원점, Godot 인스턴스를 검토했다. 샤워기/병은 선반에서 GLB의 최저점이 바닥에 맞도록 각각 0.130/0.074m 올리고 수건은 0.002m 올렸다.

- `scripts/v4/fp_tool_view.gd`가 자산 경로와 손목 자세/모션을 한 곳에서 관리한다. 임시 실린더/상자 도구 코드는 제거했다.
- 도구는 오른손 손목의 자식이며 변환을 역보정해 쥐는 위치를 보존한다. 수건의 왼손도 같은 변환을 따라 천에서 떨어지지 않는다.
- 집기 0.42초: 화면 아래에서 들어 올려 멈춤. 샤워기는 작은 조준 흔들림, 샴푸는 기울임, 수건은 양손 좌우 닦기. 사용을 멈추면 중립 자세로 복귀한다.
- Q 반납 0.28초: 손과 도구를 아래로 내린 다음 기존 방식대로 선반에 반환한다. 다른 도구로 교체할 때 이전 양손이 내려간 후 새 양손을 올려 네 손이 겹치지 않게 했다. 선택/사용 해제 상태는 즉시 바뀐다. 빠른 재선택 때 오래된 반납 뷰가 현재 도구를 선반에 복제하지 않는다.
- 숨은 도구의 StaticBody collision layer도 끈다. 선반에 복귀하면 원래 layer를 복구한다.
- 강조용 재질을 인스턴스별·surface별로 복제한다. 민트/분홍/라벨 등 원래 재질을 유지하며 선반 강조가 손에 든 모델로 번지지 않는다.
- `_tool_tip()`은 샤워기 실제 분사구 `(0, 0.093, -0.028)`를 따라간다.
- `TOOLS`의 채널·붓 반경·rate와 `use_tool_at()`, 완료 임계값은 유지했다. 샤워기 적시기 → 샴푸 → 샤워기로 헹구기 → **수건 말리기** 순서가 그대로다. 기존 완료 반응, R 새 강아지, 진행 HUD도 유지한다.

## 제약과 미검증

- 손은 펼친 정적 모델이다. 손목 이동·회전과 손바닥 받침으로 표현했으며 **손가락 굽힘, 병 압착, 수건 변형, 팔/IK는 구현하지 않았다**. 집기는 화면 아래에서 들어 올리는 연출이고, Q는 기존 선반 자동 반환 방식이다. 선반까지 손이 뻗는 실제 팔 애니메이션은 아니다.
- 사진/영상은 자동 시점·입력으로 실행했다. 사람이 직접 WASD/마우스로 장시간 플레이하는 손맛 평가는 남아 있다.
- Windows/Steam Deck 실기, 하드웨어 GPU별 그림/성능, Steam 연동은 검증하지 않았다. 소프트웨어 렌더 기록으로 제품 성능을 추정하지 않는다.
- 최초 헤드리스 썸네일 오류는 엔진 측 제한으로 남는다. 이번 테스트/실행에서는 이전 보고의 signal 11 충돌이 재현되지 않았지만 다른 환경까지 해결됐다고 단정하지 않는다.

```bash
GODOT=/path/to/Godot_v4.4.1-stable_linux.x86_64 tests/run_tests.sh
# 사용 가능한 X/Wayland 디스플레이에서 기본 Mobile 렌더러로 촬영

  --write-movie /tmp/v4.avi tools/art/capture_v4.tscn
```
